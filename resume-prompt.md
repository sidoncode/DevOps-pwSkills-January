1. End Goal

Create a one-page, ATS-friendly resume for a fresher DevOps engineer applying to Indian IT companies (service-based firms like TCS/Infosys/Wipro and product-based startups), optimized to pass automated resume screeners and land shortlists for DevOps/Cloud/SRE trainee roles.

2. Context
I am a fresher (0–1 year experience, including internships) targeting DevOps roles in India.
My background: [mention degree — e.g., B.Tech in CSE/IT, college name, CGPA, graduation year].
Skills I have: [list tools — e.g., Linux, Git, Docker, Kubernetes, Jenkins, AWS/Azure, Terraform, Ansible, CI/CD, Python/Bash scripting, monitoring tools like Prometheus/Grafana].
Projects/internships: [briefly describe 2–3, e.g., "Built a CI/CD pipeline for a Node.js app using Jenkins and Docker, deployed on AWS EC2"].
Certifications (if any): [e.g., AWS Certified Cloud Practitioner, RedHat, Kubernetes CKA].
Target companies/roles: [e.g., product startups, MNC service companies, or specific job postings].
3. Source

Base the resume structure on:

Standard Indian fresher resume conventions (education-first format, since work history is limited).
ATS-compatible formatting (no tables/graphics/columns that break parsing).
Reference points: typical Naukri/LinkedIn fresher DevOps resumes, and job descriptions from Indian companies hiring DevOps freshers (I can share a JD if needed).
Keep it to standard sections: Contact Info → Summary/Objective → Technical Skills → Projects → Internships → Education → Certifications → Achievements (if any).
4. Expectations
Length: strictly 1 page.
Format: clean, single-column, ATS-parsable (no images, icons in text, or fancy tables).
Tone: concise, action-verb-driven bullet points (e.g., "Automated," "Configured," "Deployed") with quantifiable impact where possible (e.g., "reduced deployment time by 40%").
Include a skills section grouped by category (Cloud, CI/CD, Containerization, Scripting, Monitoring, OS).
Highlight projects prominently since work experience is minimal — treat them like mini job entries with tech stack + outcome.
Avoid generic fresher-resume clichés ("hardworking," "team player" without proof).
Output as plain text/markdown first so I can review before formatting into Word/PDF.
